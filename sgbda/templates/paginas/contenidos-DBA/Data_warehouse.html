Guía Data Warehouse

Esta guía presenta de manera sencilla los conceptos esenciales de un Data Warehouse (DWH), así como los conocimientos principales que se deben manejar para poder participar en un proyecto de este tipo. A continuación se mostrará el contenido a tener presente:

01

¿Qué es un Data Warehouse?

Un Data Warehouse es un repositorio centralizado de información, diseñado para almacenar datos históricos provenientes de distintas fuentes (bases de datos transaccionales, archivos planos, APIs, entre otros), con el fin de facilitar el análisis, la generación de reportes y la toma de decisiones del negocio.

Características Principales

- Orientado a temas: organiza la información por áreas de negocio (ventas, clientes, inventario), no por procesos aislados.

- Integrado: unifica datos de múltiples orígenes bajo un mismo formato y estándar.

- Histórico: conserva la información a través del tiempo, permitiendo comparar periodos.

- No volátil: una vez cargada la información, no se modifica ni se elimina como en un sistema transaccional.

02

Diferencia entre OLTP y OLAP

Para entender un Data Warehouse es indispensable diferenciar entre los sistemas transaccionales (donde nace la información) y los sistemas analíticos (donde se consulta y se explota la información).

OLTP (Online Transaction Processing)

Sistemas usados en el día a día operativo (por ejemplo un aplicativo de ventas o un ERP). Se caracterizan por manejar muchas transacciones pequeñas, cortas y frecuentes: INSERT, UPDATE, DELETE. Su modelo suele estar normalizado para evitar redundancia.

OLAP (Online Analytical Processing)

Sistemas usados para el análisis de grandes volúmenes de información histórica. Predominan las consultas de lectura (SELECT), muchas veces con agregaciones y cruces entre varias tablas. Su modelo suele estar desnormalizado, buscando velocidad de consulta más que ahorro de espacio.

03

Arquitectura General de un Data Warehouse

De manera general, un flujo de Data Warehouse pasa por las siguientes capas antes de llegar al usuario final que consume la información.

Capas del Flujo

1. Fuentes de Datos: sistemas transaccionales, archivos planos, APIs, servicios externos.

2. Staging Area: zona intermedia donde se aterrizan los datos "en crudo", tal cual llegan de la fuente, antes de transformarlos.

3. ETL / ELT: proceso encargado de extraer, transformar y cargar la información hacia el modelo final.

4. Data Warehouse: repositorio central ya modelado (hechos y dimensiones) con la información integrada.

5. Data Marts: subconjuntos del DWH enfocados en un área específica del negocio (ventas, finanzas, RRHH), usados para simplificar el análisis de cada área.

6. Capa de Presentación: herramientas de reportes o BI (Power BI, Tableau, entre otras) donde el usuario final consulta la información.

04

Modelamiento Dimensional: Hechos y Dimensiones

El modelo dimensional es la forma más común de estructurar un Data Warehouse. Se basa en dos tipos de tablas: tablas de hechos y tablas de dimensiones.

Tabla de Hechos (Fact Table)

Contiene las métricas o mediciones del negocio (por ejemplo: valor de la venta, cantidad vendida). Cada registro suele representar un evento y se relaciona con varias tablas de dimensión a través de llaves foráneas.

Tabla de Dimensión (Dimension Table)

Contiene los atributos descriptivos que dan contexto al hecho (por ejemplo: cliente, producto, fecha, tienda). Permiten filtrar, agrupar y analizar los hechos desde distintas perspectivas.

Esquema Estrella vs Esquema Copo de Nieve

- Esquema Estrella (Star Schema): una tabla de hechos central conectada directamente a varias tablas de dimensión desnormalizadas. Es el más usado por su simplicidad y velocidad de consulta.

- Esquema Copo de Nieve (Snowflake Schema): las dimensiones se normalizan y se dividen en subtablas relacionadas entre sí. Ahorra espacio, pero agrega complejidad y más `JOIN` en las consultas.

Ejemplo_Esquema_Estrella.sql 

-- Tabla de dimension: Cliente
CREATE TABLE Dim_Cliente (
    ClienteKey    INT PRIMARY KEY,
    NombreCliente VARCHAR(100),
    Ciudad        VARCHAR(50),
    Segmento      VARCHAR(50)
);

-- Tabla de dimension: Producto
CREATE TABLE Dim_Producto (
    ProductoKey   INT PRIMARY KEY,
    NombreProducto VARCHAR(100),
    Categoria     VARCHAR(50)
);

-- Tabla de dimension: Fecha
CREATE TABLE Dim_Fecha (
    FechaKey INT PRIMARY KEY,
    Fecha    DATE,
    Anio     INT,
    Mes      INT,
    Trimestre INT
);

-- Tabla de hechos: Ventas
CREATE TABLE Fact_Ventas (
    VentaKey     INT PRIMARY KEY,
    ClienteKey   INT REFERENCES Dim_Cliente(ClienteKey),
    ProductoKey  INT REFERENCES Dim_Producto(ProductoKey),
    FechaKey     INT REFERENCES Dim_Fecha(FechaKey),
    Cantidad     INT,
    ValorVenta   DECIMAL(18,2)
);
05

Proceso ETL / ELT

Es el proceso encargado de mover la información desde las fuentes hasta el Data Warehouse, garantizando que llegue completa, correcta y en el formato adecuado para el análisis.

Etapas del Proceso

E - Extracción: se obtiene la información desde las fuentes de origen (bases de datos, archivos, APIs).

T - Transformación: se limpia, valida, estandariza y transforma la información (tipos de dato, nulos, duplicados, reglas de negocio).

L - Carga: se inserta la información ya transformada dentro de las tablas de hechos y dimensiones del Data Warehouse.

- En el enfoque ELT (Extract, Load, Transform) la transformación se hace después de cargar los datos "en crudo", aprovechando el poder de cómputo de plataformas modernas en la nube.

06

Herramientas Comunes en Proyectos de DWH

En un proyecto de Data Warehouse suelen combinarse distintos tipos de herramientas, dependiendo de la etapa del proceso.

ETL / Orquestación

SQL Server Integration Services (SSIS), Talend, Informatica PowerCenter, Apache Airflow, Azure Data Factory.

Motores / Plataformas de Datos

SQL Server, Oracle, PostgreSQL, Snowflake, Google BigQuery, Amazon Redshift, Databricks.

Visualización / BI

Power BI, Tableau, Looker, Qlik Sense.

Modelamiento

Erwin Data Modeler, dbt (data build tool), diagramas entidad-relación tradicionales.

07

Qué Necesitas Saber para Participar en un Proyecto de DWH

Estos son los conocimientos y habilidades principales que se esperan de alguien que va a participar en un proyecto de Data Warehouse, ya sea en el rol de desarrollador ETL, modelador de datos o analista.

Conocimientos Clave

- SQL avanzado: subconsultas, funciones de ventana (`window functions`), agregaciones, optimización de consultas.

- Modelamiento dimensional: saber identificar hechos, dimensiones, granularidad y llaves subrogadas (`surrogate keys`).

- Procesos ETL/ELT: entender cómo extraer, limpiar, transformar y cargar información de forma eficiente y controlada.

- Calidad de datos: validar consistencia, duplicados, valores nulos y reglas de negocio antes de publicar la información.

- Entendimiento del negocio: comprender qué necesita analizar el área solicitante, para modelar la información de forma útil y no solo técnica.

- Rendimiento: conocer buenas prácticas de índices, particionamiento y agregaciones para que las consultas analíticas sean rápidas.

- Documentación: mantener diccionarios de datos y documentar el linaje de la información (`data lineage`), de dónde viene y cómo se transformó cada dato.
